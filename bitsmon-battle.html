STEP 1 — STRUKTUR FILE

Struktur file setelah modularisasi:

bitsmon dpv2/ ├── data/ │ ├── player.json ← stat player │ └── enemies.json ← array 4 musuh (wave) ├── js/ │ ├── ai/ │ │ ├── config.js ← AI_MODE enum + setMode() │ │ ├── decision.js ← chooseAction() utama │ │ └── helper.js ← dpSearch(), applyAction(), dll │ ├── core/ │ │ ├── battle.js ← runBattle() per wave (Node.js) │ │ └── damage.js ← calculateDamage() │ ├── battle-ai.js ← AI engine (browser, ES module) │ ├── battle-renderer.js← Canvas pixel-art renderer │ └── battle-ui.js ← Game state, loop, UI controls ├── css/ │ └── battle.css ← Stylesheet terpisah └── bitsmon-battle.html ← HTML murni

STEP 2 — ALGORITMA: GREEDY vs HYBRID DP

Mode GREEDY: pilih aksi dengan damage terbesar sekarang, tanpa lookahead.

Mode HYBRID: Greedy + DP Memoization — eksplorasi 4 gilir ke depan dengan shared memo Map.

// GREEDY — evaluateImmediate function evaluateImmediate(action, player, enemy) { if (action.type === "basic") return player.attack; if (player.attack >= enemy.hp) return player.attack - 1; return action.data.damage; } // HYBRID — dpSearch (DP dengan Memoization) // Key: "playerHp|playerSp|playerEnergy|enemyHp|depth" // Nilai dibulatkan ke kelipatan BUCKET_SIZE=5 agar // overlapping subproblems lebih sering ter-cache hit.

STEP 3 — applyAction (resource sesuai helper.js)

Perubahan resource per aksi (sesuai js/ai/helper.js):

basic → energy += 30 | sp += 1 skill → sp -= sp_cost | energy += 10 ultimate→ energy -= energy_cost
⚠ Berbeda dari versi battle.js Node.js (basic: energy+20, skill: energy+25)
